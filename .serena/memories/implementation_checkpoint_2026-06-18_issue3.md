## 最重要の意思決定

- **二系統の時計を分離**（正典 `docs/decisions/architecture.md` §3.2・§6）。ゲームの時計は `player.timer.position`（楽曲再生位置）を源泉とし、平滑化・単調化・ずれ補正したもの。操作音の時計 `AudioContext.currentTime` は別系統（Issue #52）であり本実装は関与しない。
- **時間源の供給は Issue #4 の責務**。本実装は接合面 `TimeSource`（`positionMs`・`isPlaying`・`isReady`）までを作り、Issue #4 が `player.timer.position` と `player.isPlaying` を読む実装へ差し替える。M0 時点では統括が「常に未確定（isReady 偽）」の仮実装を注入し、世界は進まずUIだけ実時間で進む。
- **「楽曲の停止」と「描画ループの停止」を分ける**（一時停止仕様 #112 に伴う確定）。手動一時停止は `isPlaying` が偽の状態で、描画ループは止めない（停止中表示と再開カウントインを実時間で進めるため）。描画ループを止めるのはタブ非表示・ページ退避のときだけ。
- **一時停止はプレイ画面内のオーバーレイで表し、新しい画面状態は追加しない**（5状態を維持）。再開はウォームアップと同じ3-2-1カウントインの表現の後に楽曲へ戻す。一時停止中の入力は得点・ゲージ・投下・タップ総数に入れず、得点に影響しない。実装は Issue #112 が担う。

## 採用した数値とその理由（すべて理由を先に述べる）

- 固定時間刻み = 10ミリ秒: 満点とする判定の許容幅は前後40ミリ秒。状態の進行を判定窓の内側で複数回解像するため満点窓の4分の1とする。減衰外端90ミリ秒も10で割り切れ、毎秒100刻みで負荷も小さい。★暫定。
- フレーム時間差クランプ上限 = 100ミリ秒: 既存の暫定ループの値と既存スモークテストのタイムアウト算定（最悪毎秒5フレーム想定）がこの値に依存するため維持する。
- 再同期閾値 = 200ミリ秒: 位置報告の更新粒度（おおむね50ミリ秒から100ミリ秒）の揺れで誤って再同期しないよう更新粒度の約2倍を採り、シークやタブ復帰の数百ミリ秒以上の飛びだけを捕捉する。★暫定。
- 平滑化係数 = 0.2: 毎フレーム（約16.7ミリ秒）で報告値へ急追従すると時計が階段状に揺れるため一次低域通過で吸収する。0.2 は差が1フレームごとに約2割縮む設定で、時定数は概ね約83ミリ秒（報告更新粒度と同程度）。★暫定。
- 停止中再同期閾値 = 10ミリ秒（固定時間刻みと同値）: 停止中は予測誤差が無く報告位置のゆらぎは無視できるため、1刻みを超える変化は実際の位置移動とみなして再同期する。★暫定。
- 1フレームの最大刻み回数 = 14: 通常フレームでゲーム時間が進む最大量はクランプ上限100ミリ秒に平滑化補正の最大量（再同期閾値200ミリ秒×係数0.2＝40ミリ秒）を加えた140ミリ秒。これを固定時間刻みで割って導出する（定数を変えても整合）。

## レビューと修正（事実）

- 計画段階で Codex のゼロベース設計レビューを複数回受け、累積器を「絶対ゲーム時刻へ進める方式」へ再構築、再同期時の world 同期、上限超過の余剰を捨てず現在時刻へ合わせる、停止中の小さなシークの再同期、診断状態に ready と hasClockSample を追加、毎フレーム判定を描画合図・タブ表示非依存の関数に分離、を反映済み。
- 実装後の Codex レビューで判明したものを修正済み。`clock.forceResync` を真偽返却にし、再生開始分岐と再開で位置が無効なときは同期も計上もせず次の有効フレームへ持ち越す。`start` を冪等化。テストに、結合レベルのフレーム数非依存、タブ復帰で世界の時刻が現在の再生位置へ一致、実経過のクランプ、後始末の冪等と購読解除回数、再開時の二重発火防止、境界（再同期閾値ちょうど・1刻みちょうど・過去目標）を追加。
- 最終の Codex レビューは「コミット可」。残点として挙がったテストヘルパーの no-op 結線も、本番と同じ `world.step` 結線へ直し通常刻みの結合検証を追加して解消済み。
