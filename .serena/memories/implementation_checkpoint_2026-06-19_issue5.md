## 最重要の意思決定

- **最小ゲート方式**: 統括 `src/app/index.ts` は従来どおり起動時に既定曲 TAKEOVER を先読みする。曲選択は「実装済み曲だけ開始でき、未実装曲は無効化する入口」とし、選んだ曲がロード対象を切り替える改造はしない。複数曲の切替ロードはマイルストーンM8（横展開）で統括側を差し替えて導入する。本マイルストーンM0の目的がTAKEOVERのロードと再生であり、切替ロードは別マイルストーンの範囲だからである。
- **曲ボタン直接開始**: タイトル画面は6曲を縦一覧で並べ、実装済み曲のボタン自体に開始操作を割り当て、押すと即ウォームアップへ進む。未実装曲は押せない無効ボタンに「準備中」を表示する。受け入れ基準本文の「Coming soon」を、対象読者である日本語話者に明確な「準備中」で実装する（無効化された状態そのものが基準を満たす）。
- **実装可否は `Song` のデータ**: `src/config/songs.ts` の `Song` に必須の真偽値 `implemented` を加え、6曲すべてが状態を明示する。未実装曲の無効化は曲ごとの属性であり、値の定義を責務とする `config` に置くため。任意項目でなく必須にして、新曲追加時の宣言漏れを型検査で検出する。実装済みはTAKEOVERのみ。
- **画面文脈を曲カタログへ拡張**: `src/screens/types.ts` の `ScreenContext` から `songTitle` を外し、表示用の最小カタログ `songs`（鍵・曲名・作者名・実装可否の読み取り専用配列）と要素型 `SongChoice` を渡す。画面層へロードURLや音楽地図IDは渡さず、統括が `SONGS` から写し取る。描画・画面層が楽曲ロードの詳細を知らない依存方向（`docs/decisions/architecture.md` §5）を保つため。
- **最小ゲートの整合を不変条件テストで固定**: 「実装済み曲はちょうど1曲で、そのキーが `DEFAULT_SONG_KEY` と一致する」を `src/config/songs.test.ts` で縛る。実装済み曲が既定曲以外に増えると、その曲のボタンが開始操作を持つのに統括は既定曲しか先読みせず、UIが示す曲と再生される曲が食い違うため。将来M8で2曲目を実装可能にするときは、切替ロードの導入とこのテストの更新が同時に強制される。

## 実機手動確認で判明し併せて修正した再生UXの不具合4点

不具合2〜4は Issue #4 で実装した再生抽象（`src/textalive`・`src/app`）の挙動に属する。

1. **タイトル画面が画面に収まらず拡大率を下げないとボタンが見えない**（`src/style.css` のみ）: スクロールや拡大率変更に頼らずレスポンシブで6曲を可視領域に収める。`#app` の高さを動的ビューポート高（`100dvh`、フォールバック付き）に。`.song-list` を適応グリッド `repeat(auto-fit, minmax(min(100%, 14rem), 1fr))` にして縦長は1列・幅広は2〜3列。余白に `env(safe-area-inset-*)` と画面高連動の `clamp()`。低い画面（`@media (max-height: 600px)`）で見出し・間隔を圧縮。曲名・作者名は1行＋省略表示で折り返しによる縦膨張を防止。タイトル固有の規則は `.screen--title`・`.song-list`・`.song-choice` に閉じ、他画面へ波及させない。
2. **ウォームアップ中に音が鳴る**（`src/textalive/textAlivePlayback.ts`）: 自動再生制限の解除に必要な「利用者操作中の再生」を音量0で無音のまま行う。再生用音量はプレイヤー生成直後に一度だけ捕捉（消音中の0を再捕捉して無音再生になる破綻を防ぐため）。
3. **「触れて再生」が触れても消えず再表示を繰り返す**（`src/app/index.ts`）: 「触れた」を表す状態を持ち、押下で即非表示にし、このプレイ中は再表示しない。`enterPlay` で状態を戻す。利用者要件「一度触れたら再表示しない」に直接合致するため、再生開始の成否に依らず再表示しない。
4. **操作なしで「触れて再生」が出ながら同時に再生される**（`src/textalive/playback.ts`・`textAlivePlayback.ts`）: 再生開始の判定を再生イベント `onPlay` の遷移だけに頼らず、実再生状態 `player.isPlaying` からも成立させる（純粋関数 `latchStarted` を追加し単体テスト）。`onPlay` は「再生中でない状態から再生中へ移る」遷移でのみ発火し既に再生中では発火しないため、許可確立の無音再生がプレイ進入まで続くと再生中なのに開始未成立と判定され誤表示されていた。途中位置の音漏れは、音量復元を「再生中かつ再生位置が先頭付近に達してから」に保留して防ぐ。

## 採用した数値とその理由（すべて理由を先に述べる）

- 適応グリッドの列の最小幅 = `min(100%, 14rem)`: 14rem（224画素）を列の最小幅にしつつ、容器が極端に狭いときは100%へ縮めて横はみ出しを防ぐため。
- 低い画面の圧縮の閾値 = 高さ600画素: 横向きの携帯（高さおよそ320〜430画素）と小型の縦向き端末（高さおよそ568〜640画素）を含め、既定の大きさでは収まりにくい高さの上限として採る。
- 音量を再生用音量へ戻す再生位置の上限 = 1000ミリ秒: 先頭への移動が反映された後に数フレーム進んだ程度の位置を十分に含み、かつ許可確立の無音再生がウォームアップ全体のおよそ5000ミリ秒続いた場合の途中位置を確実に下回る区切りだから。
