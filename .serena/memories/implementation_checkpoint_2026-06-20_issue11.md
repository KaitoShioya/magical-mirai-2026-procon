## 最重要の意思決定

- **本編描画パイプラインへの組み込み**: Issue #11 は本番の単一描画領域 `src/rendering/renderRoot.ts` の描画を、レンダラ直描画から合成器（`EffectComposer`）経由へ切り替える作業である。合成は専用モジュール `src/rendering/bloom.ts` に分離し、後続 #15（描画層合成）が再利用できるようにした。#15 が担う「3次元描画→深度消去→2次元正射影」のパス順合成は本Issueでは先取りしない（`src/rendering/README.md` の依存規則）。
- **パス順とパイプライン一本化**: 合成器に「シーン描画 → ブルーム → 最終出力」の各パスをこの順で積む。本編の `render()` は常に合成器経由に一本化し、ブルームの有効・無効で色管理の経路を分けない。無効化は最終出力パスを残したままブルームのパスだけを無効にする。合成器は最終の有効パスを画面出力へ切り替えるため、無効時はブルームの寄与だけが無くなり色管理は維持される。
- **起動時パラメータでの切替**: 入口 `src/main.ts` が起動時パラメータ `bloom` を解釈し、値が文字列 `0` のときだけ無効、未指定や他値は有効（既定有効）。統括 `src/app` と描画基盤 `src/rendering` へ受け渡す。受け入れ基準が `bloom=0` を無効条件と明示するための判定である。
- **判定・時刻の論理を持たないビュー**: `bloom` は `profiles`・`tools` を import せず、診断状態を返すだけにする（`docs/decisions/architecture.md` §5）。決定的に検証できる解像度算出は three.js 非依存の純粋関数として `src/rendering/viewport.ts` に置く（雨が自前の純粋関数を持つのと同じ方針）。

## 採用した数値とその理由（すべて理由を先に述べる）

- ブルームの強さ1.2・広がり0.6・明るさの下限0.5: これらは Issue #11 の技術要件に明示された値であり、試作 `src/tools/perf/main.ts` で狙いの見えを確認済みのため、その値をそのまま採る。
- 入力解像度の倍率0.5（画素密度倍率を掛けない）: ブルームのぼかしのコストは描画対象の面積に比例する。表示寸法（CSS画素）を基準に半分へ抑えると、画素密度の高い端末ほどブルームが相対的に安くなり、毎秒60フレームの目標に資する。計測済みの試作も同じ基準で解像度を決めているため計測値を引き継げる。式は「幅 = max(1, floor(表示幅 × 0.5))」「高さ = max(1, floor(表示高 × 0.5))」。floor は描画対象の寸法が整数画素数のため、max(1, …) は寸法0で描画対象の生成が壊れるのを避けるため。
- 半解像度をパス追加直後とリサイズ後の双方で再適用する: 合成器はパス追加時とリサイズ時に各パスへ描画バッファ全解像度を設定するため、構築時の解像度だけでは半解像度が上書きされ失われる。よって両時点で半解像度を明示的に再適用する。
- リサイズ時の合成器の画素密度更新は変化時のみ: 合成器の画素密度更新は内部で寸法再設定を再実行し往復バッファを再確保するため、画素密度倍率が変化したときだけ呼んで無駄な再確保を避ける。合成器は構築時の画素密度を保持し寸法再設定では読み直さないため、倍率変化時には更新が必要である。
- 診断状態の入力解像度は「ぼかしへ渡す入力値」を指す: `UnrealBloomPass` は内部で描画対象を round(入力÷2) からさらに半減させるため、診断項目名を `bloomInputWidth`・`bloomInputHeight` とし、内部描画対象の寸法ではなく入力値であることを明示した。

## レビューと検証（事実）

- 計画段階で Codex のレビューを2巡反映: 最終出力パスの必要性（線形からsRGBへの色空間変換とトーンマッピングを担う。これが無いとブルーム有効時に画面が暗く沈む）、半解像度をパス追加直後にも再適用する必要（パス追加が全解像度で上書きするため）、画素密度更新を変化時のみに限定、診断状態への最終出力パスの有効可否の追加、後始末順序の根拠明記。
- 実装後の Codex レビューで軽微な改善を反映: 最終出力パスより前に位置する `RenderPass` も破棄処理の対称性のため明示破棄（基底クラスの破棄は何もしない実装で安全であり、将来の資源追加に備える）、画素密度更新の前提と半解像度再適用の順序の意図をコメントで明文化、スモークの照合に使う表示寸法が CSS画素であることをコメントで明示。
- `npm run typecheck`（厳格・両設定）: 型エラーなし。
- `npm run test`（vitest）: 全件通過（最新mainへのリベース後230件）。`computeBloomResolution` の単体テスト（半分・小数切り捨て・下限1・非有限と0以下の丸め）を含む。
- 本番ビルド（Node 22）: 成功。ブルームの後処理が本編バンドルに取り込まれる。
- スモーク（Playwright）: 描画スモークで既定有効・3パラメータ・最終出力パスの有効・入力解像度が表示寸法の半分・`bloom=0` での無効を確認。画面遷移スモークとエンジンループスモークも成功（起動経路の回帰なし）。
