## 最重要の意思決定（理由を先に述べる）

- **配置を `src/utils/beatScheduler.ts` にする**: 本モジュールは時刻に基づく純粋なイベントの仲介であり、依存規則（`architecture.md` §3.3・§5）で描画の層は判定・得点・時刻の論理を持てないため描画の層には置けない。`src/utils` の責務は数値計算とイベントの仲介を含み、描画と判定が共有する純粋評価器であるカメラ軌跡評価器（#13）を同じ理由で `src/utils` に置いた前例に倣う。Issueラベルは area:rendering だが、上記の依存規則と前例により `src/utils` を採る（着手前にユーザー承認済み）。
- **実装範囲は独立モジュールと単体テストのみ**: 消費側（拍同期のビネットと色収差 #17、画面の拡大と減衰する揺れ #76、1文字を1拍ずつ表示する演出 #23）と本編結線 #59 は別Issue。雨環境 #12・カメラ軌跡 #13 と同じく、基盤を単体で完成させ本編結線は後続へ委ねる（着手前にユーザー承認済み）。純粋ロジックのため、描画を伴わない単体テストで受け入れ基準を満たせる。
- **駆動単位を描画フレームにする**: `research 02 §2` が「毎フレームで再生位置を見て、直前の拍を跨いだフレームで1回だけ発火」と定める。発火対象は判定・得点ではなく視覚演出であり、`architecture.md` §6「描画の繰り返しの時刻は演出にのみ使い判定の基準にしない」に従い、判定用の固定時間刻み（`src/engine/scheduler.ts`）ではなく描画フレーム単位で駆動する。
- **入力は拍開始時刻のミリ秒の昇順配列のみ**: TextAlive（`player.getBeats()` の各 `startTime`）と曲プロファイル（#46 生成、未完成）の双方から独立させる。これにより #46 の完成を待たず本Issueを完結できる。
- **飛び（再生位置のシーク・再同期・タブ復帰）は `advance` でなく `syncTo` で基準を貼り直す**: 視覚演出を遡って一括発火させないため。この呼び分けは本編結線 #59 が `src/engine/loop.ts` の `FrameOutcome.didResync`（再同期フレーム）と再生開始フレームを見て行う。

## 採用した仕様とその理由（すべて理由を先に述べる）

- **発火区間は「直前に処理した時刻を含まず、現在時刻を含む」左を開き右を閉じた区間**: `research 02 §2`「拍を跨いだフレームで1回だけ」を満たすには、跨ぎを「直前の処理時刻 < 拍の開始時刻 ≦ 現在時刻」と定義すればよい。各拍はちょうど跨いだ1フレームで1回だけ発火し、境界での二重発火と取りこぼしを防げる。
- **時刻の単位はミリ秒で統一し変換を挟まない**: TextAlive の拍の開始時刻と再生位置がともにミリ秒のため。
- **未確定の基準時刻は `null` で表す**: 既存の時計（`clock.ts` の `estimate: number | null = null`）が未初期化を `null` で表す前例に合わせ、有限でない値と明確に区別するため。
- **入力配列は生成時に複製する**: 引数の型は実行時の配列変更を防げず、生成後に呼び出し側が元配列を変更すると発火が壊れる。生成時に値を複製して以後は内部配列だけを参照する（カメラ軌跡評価器が `times` を複製して保持する前例に合わせる）。
- **有限値の扱いを生成時と毎フレームで分ける**: 生成時は各要素が有限でない、または昇順（非減少）でない場合に例外を投げる（内容の不備を実行時に黙って壊れさせるより生成時に明確に失敗させるため。`architecture.md` §3.6）。毎フレームの `advance` と `syncTo` は、渡された時刻が有限でなければ無発火で状態を変えず戻る（描画ループを例外で止めないため。`clock.ts`・`scheduler.ts` が有限でない入力を早期に弾く前例に合わせる）。
- **次に未処理の拍の添字を保持し、`syncTo` は二分探索で位置づける**: 毎フレームの前進は発火数に比例する計算量で済み、飛びの貼り直しは `firstBeatIndexAfter`（指定時刻より厳密に後の最初の添字）で対数時間に収まる。
- **発火イベントに拍の開始時刻からの経過（発火フレームの時刻 − 拍の開始時刻、常に0以上）を含める**: フレーム落ちや再同期で発火フレームが拍より遅れることがあり、消費側 #23 がこの経過分だけ演出を進めて開始することで拍からの見かけのずれを補正できる。
