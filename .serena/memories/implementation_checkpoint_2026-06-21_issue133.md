## 位置づけ

マイルストーンM3「キネティックタイポグラフィエンジン」の歌詞インターフェースである。TextAlive が提供する歌詞構造（フレーズ・単語・文字の入れ子）を、TextAlive のオブジェクト参照に依存しない平易な歌詞タイムラインへ変換し、再生位置（ミリ秒）から発声中の歌詞単位を引けるようにする曲非依存の純粋モジュールを提供する。下流の曲固有タイポ譜面（#33）、本編通しプレイ（#59）、表示同期の品質ゲート（#99）がこの出力を消費する。再生抽象 `Playback`（src/textalive）は時間源と読み込み状態のみを公開し歌詞データを供給しないため、歌詞データはこのモジュールが別に供給する。

## 最重要の意思決定

- **配置先は `src/textalive/lyricsTimeline.ts`**: アーキテクチャ §4 の最上位ディレクトリ表は固定の集合であり歌詞専用のディレクトリを持たない。`textalive-app-api` に依存してよいのは `src/textalive` のみであり、歌詞構造の抽出はこの層の責務に収まる。下流へは TextAlive のオブジェクトでなく平易なデータで渡るため依存規則 §5 に反しない。
- **入力は最小の構造型に閉じ、TextAlive のパッケージを型を含め一切 import しない**: 構築関数はフレーズ・単語・文字が持つ最小の項目（text・startTime・endTime・子の配列）だけを要求する構造型を入力に取る。実 IVideo がこの型を構造的に満たすことはパッケージ型定義 `node_modules/textalive-app-api/dist/textalive-app-api.d.ts` で確認済みであり、実 player.video をそのまま渡せる。差異の吸収が要る場合でもそれは本編結線 #59 の責務とする。これにより本モジュールは TextAlive 非依存で単体検証できる。
- **走査は phrase.children と word.children のみ、word.next と char.next を使わない**: word.next・char.next はフレーズ境界を越えて曲全体を辿り重複が発生する既知の罠を避ける。モジュール本文に文字列 `.next` と TextAlive のパッケージ名が現れないことを回帰テストで守る。
- **識別子は走査順の番号であって文字列ではない**: 各単位に走査順の番号（フレーズ番号・単語番号・文字番号）と曲全体の通し番号を与える。歌詞には同じ文字が何度も現れるため、識別子を文字そのものの文字列にすると一意にならない。
- **構築と検査の分離**: 構築関数 `buildLyricsTimeline` は入力の整合性を検査せず数値と文字列を値として忠実に写し、入力の参照を保持せず並べ替えもしない。整合性の確認は別の純関数 `findLyricsTimelineIssues` が担い、品質ゲート #99 と本編結線 #59 がこれを呼ぶ。曲プロファイル検査 `validateProfile.ts` の流儀（例外を投げず不整合の一覧を返す）に合わせる。
- **実再生との結線はスコープ外**: onVideoReady の後にタイムラインを構築して供給する配線は #59 の責務とし、本変更には含めない。本変更は結線の入口を README に文書化するに留め、未使用の配線コードは作らない（ユーザー承認済みのスコープ）。

## 採用した数値とその理由（すべて理由を先に述べる）

- 時刻の項目名を `startTimeMs`・`endTimeMs` とする: TextAlive の startTime・endTime は既にミリ秒単位であり、曲プロファイルのスキーマもミリ秒の項目に接尾辞 Ms を付ける規約を持つ。この規約に揃えて消費側での単位の取り違えを防ぐ。数値の変換は行わず項目名の正規化だけを行う。
- 時刻探索は範囲に含む単位のうち開始時刻が最も大きいものを返し、両端を含む: 両端を含めるのは境界ちょうどの時刻でも単位に帰属させ無音でない瞬間に必ず歌詞単位を返すためである。開始時刻が最も大きいものを選ぶのは、前の単位の終了時刻と次の単位の開始時刻が等しい共有境界で新しく始まった側を発声中の単位とするためである。
- 整合検査の時刻比較に許容誤差を設けない（厳密に比較する）: 音楽地図は隣接単位の共有境界に同一の数値を再利用しており、浮動小数点の表現を含めて前後で同一である。厳密な比較で共有境界を正常と分類でき、親子の入れ子も対象曲で違反が無いことを確認できる。許容誤差を入れると本物の小さな誤りを見逃す危険だけが増える。この根拠は1曲目TAKEOVERのデータに基づくため、他曲へ横展開する際は同じ前提でよいか再確認する。
- 時刻に有限の数値を要求する: 数でない値や正負の無限大は大小比較が常に偽になり壊れた時刻を見逃すため、各単位の開始時刻と終了時刻が有限の数値であることを検査する。曲プロファイル検査も時刻に有限の数値を要求しており、これに揃える。

## 実データによる事前確認（対象曲TAKEOVER、結論のみ）

`docs/analysis/takeover.songmap.json`（版管理に含まれる）で確認した。フレーズ90・単語495・文字1157（Issueの「1157字」と一致）。文字の文字列の連結が単語の文字列に、単語の文字列の連結がフレーズの文字列に一致し、不一致は無い。フレーズ同士は重ならずフレーズ間に無音区間が多数ある。隣接単位の共有境界が多く、前の終了時刻と次の開始時刻が同一の数値である。子の時間範囲は親の範囲の内側にあり、兄弟の厳密な重なりは無い。空の単語や空の文字や空の文字列は無く、全ての文字が1コードポイントである。開始時刻と終了時刻が等しいゼロ長の単位が3件ある。
