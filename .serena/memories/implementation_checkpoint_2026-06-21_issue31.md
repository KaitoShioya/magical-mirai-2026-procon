## 位置づけ

マイルストーンM3の可読性能力である。読ませる役の文字・単語・フレーズを、発光・ブルーム後処理を含む最終描画画素で不利な背景に対しコントラスト比4.5:1以上にできる能力をエンジンへ与える。具体値と配置は #33、合成は #130・#131、ゲート常時執行は #98、本編結線は #33・#59 が担い、本Issueは機構と計算部品の提供＋診断フィクスチャでの能力実証に限る。

## 最重要の意思決定

- **計算（純粋）と反映（troika）を分離**: `readability.ts`（sRGB線形化・相対輝度・コントラスト比・発光抑制・最小ワールド寸法・確定可読性指定の生成）と `readabilityRenderer.ts`（機能可否の実行時判定・Textへの反映・可読性下地）に分ける。#131 は `readability.ts` だけを取り込める。
- **既定スタイル＝明るい塗り＋全周を囲む暗い縁取り＋影**: 明るい塗りが暗い背景に、暗い縁取りと影が明るい背景とブルームのにじみにコントラストを与える。塗りを囲む暗い縁取りが背景非依存のコントラストの主手段。発光抑制（明るい成分の輝度上限）の対象は塗りに限り、縁取りと影は暗い分離側で対象外。
- **縁取り＝troika stroke、影＝troika outline のずれとぼかし**: Issue本文が独立2色を要求し影に outline のずれとぼかしを明示するための一意な帰結。使う前に実体での反映可否を実行時判定し、縁取りと影モード／縁取りのみモード／縁取りと下地モードへ確定する。troika 0.52.4 では stroke系・outline系（ずれ・ぼかし・不透明度）が全て実体に存在することを `troikaExports.test.ts` で確認済み。
- **発光抑制はパイプライン側の選択除外でなく輝度制約**: 現状パイプラインは全画面のブルームで特定物体を除外できないため、明るい成分の相対輝度をブルーム閾値（線形0.5、`rendering/constants.ts` の BLOOM_THRESHOLD）以下へ収める制約として実装する。
- **最小表示寸法は大きさの段で毎フレームの下限**: 出現時固定では合成やカメラ移動で無効化されるため、毎フレームの下限とする。適用主体は一本化し、#131 がある場合は #131 のみ、無い現段階はエンジンのみが適用する。
- **未収録文字は文字集合所属で判定**: 暖めで渡された文字集合を主フォントの収録範囲とみなし、集合の外は代替フォント（`FontEntry.fallbackName`、未登録なら troika 既定）へ回す。代替の発生件数とフォント読込失敗件数は `stats` で取得できる。troika 既定フォントは日本語字形を持たないため、統合（#33・#59）で日本語収録の代替フォント登録を前提とする。
- **読ませる役のフレーズは既定で単一文字層**: 一括描画が各文字ごとの可読性設定を持つかが不確かなため、可読性の正確さを既定にする。確認後に一括描画へ移す最適化は後続。
- **可読性下地は許容プリミティブとして定義したが、実機検証で不要と判明**: 縁取りと影だけで代表集合に4.5:1以上を達成したため `backing=none`。下地（文字形の暗い複製／単位背面の暗い面）は `readabilityNeedsBacking` で有効化でき、費用（下地数・追加文字数・追加描画面数）を診断出力へ記録する設計のみ残す。

## 採用した数値と判断方法（理由を先に述べる）

- コントラスト比は WCAG 2.1 の `(明+0.05)/(暗+0.05)`、相対輝度は sRGB を線形化して `0.2126R+0.7152G+0.0722B`。線形化する理由は、式とブルーム閾値が線形空間で定義され、最終出力段のトーンマッピングと sRGB 変換を経た画素をそのまま使うと前提と合わないため。閾値4.5:1は正典（concept-final.md・research/08）が採用済みの通常文字の適合水準。
- 色値は sRGB の16進で持ち、輝度計算で線形化する。既存エンジンが塗り色を sRGB の16進で扱うことに合わせ、sRGBと線形の取り違えを防ぐため境界を明示する。
- 発光抑制のクランプは8ビットへ切り捨てる。最近接へ丸めると量子化で輝度が上限を僅かに超えてにじむ恐れがあるため、切り捨てて各成分を目標以下にし上限超えを起こさない。
- 最小ワールド寸法はカメラ正対（遠近の縮みなし）を前提に、`P×2×D×tan(縦視野角÷2)÷画面縦画素高`。目標 P と画面縦画素高はデバイス画素（読める可否は実描画画素で決まる）。累積拡大を渡せば正確、1なら高速概算。
- 既定の縁取り幅は fontSize の4%。太いと中心線に沿う stroke が内側へ入り明るい塗りを覆うため、塗りを主に残す細さにする。

## 実機検証の結果

- `readability.html`（新規診断）＋ `scripts/readability-contrast.mjs` で、不利な背景の代表集合5種（暗い背景・明るい背景・暗から明への階調背景・ブルームで強くにじむ明るい発光塊・高周波の模様の背景）に対し、発光・ブルーム後処理を通した最終出力段の後の画素から文字内部と縁取りのコントラスト比を計測。結果は暗9.90・明9.90・階調9.90・発光塊4.69・高周波9.90、全体最小4.69で合格閾値4.5を満たす。縁取りと影だけで達成したため可読性下地は不要。
- 計測は固定条件（画面寸法・画素密度・グリフ・背景）で同一実行環境の反復に安定する。GPUやブラウザが異なると最終画素は厳密一致しないため環境間の厳密一致は保証しない（環境を記録する）。
- 性能回帰（`scripts/typography-fps.mjs`、実GPU）は desktop_real 平均60・単発落ち0、desktop_maxload 初回遅延40msで #20 の☆目標（平均55以上・単発落ち5回未満・初回遅延100ms未満）を維持。非可読の経路はエンジン変更の影響を受けない（早期returnと遅延判定で隔離）。

## CodeX静的レビューでの追加修正（2回目のレビュー反映）

CodeXによる未push実装の静的レビューで挙がった不具合を修正し、テストを追加した（全554テスト通過、可読性検証と性能回帰は再実行で合格維持）。

- P1 プール再利用での縁取り・影の残留: `applyTextProperties` で stroke系・outline系を既定値へ戻すようにした。可読性付きの文字のあと同じ Text を可読性なしの文字へ再利用しても縁取り・影が残らない。
- P1 フォント読込失敗の代替の補強: 暖め自体の失敗を try/catch で失敗に数えるようにした。`chooseFont` は代替フォント自身が失敗しているときその URL を返さず troika 既定へ回す。演出役の `spawnPhrase` の `chosen.url ?? font.url` を `chosen.url` にし、代替の null 指定が主フォントへ戻らないようにした。
- P1 setColor の発光抑制バイパス: 読ませる役の `setColor` は塗りを発光上限（`maxBrightLuminance`）以下へ収めるようにした（演出役は生色のまま）。エンジン単体でも「明るい成分はブルーム閾値以下」の不変条件を保つ。
- P2 可読性下地の追従: 最小寸法維持で文字形の暗い複製の fontSize を変えたとき `backing.sync()` を呼ぶようにした。`setScale` で下地も同じ倍率にした。下地の有無と形は出現時に確定する（生存中は変わらない）ため `applyReadability` は文字本体のみ更新する旨を明記。
- P2 診断の計測値の命名: 実態が百分位の代表値であるため `minFillBorder`→`fillBorderContrast`、`p5FillBorder`→`conservativeFillBorder` へ改名し、「最小」表記を「百分位の代表」へ正した（診断・スクリプト・globals.d.ts）。

## CodeX静的レビューでの追加修正（3回目のレビュー反映、可読性下地の追従）

CodeXの2巡目レビューでP1修正の有効性と設計の妥当性は確認済み。残った可読性下地経路（現状は無効だが要件に含む）の追従バグを修正した（全557テスト通過、下地有効の診断 ?backing=1 も実機で完了・エラー0を確認）。

- P2 setScale で単位背面の暗い面の寸法が壊れる: 下地に setScale を設け、基準寸法（fontSize）と拡大倍率の積で寸法を作り直すようにした。倍率を object.scale へ直接書いて基準寸法由来の幅・高さを失う不具合を解消。文字形の暗い複製は fontSize と scale を独立に持つ。エンジンの setEntryScale は backing.setScale を呼ぶ。
- P2 下地付き診断が文字形の暗い複製の sync 完了を待たずに計測しうる: 下地の sync に完了通知（callback）を設け、診断は被覆マスク・読ませる文字本体に加えて下地の確定も待ってから計測するようにした。
- P3 受け入れ診断の合否が Issue 文言より狭い解釈である点: 合否は「塗り対縁取り」（背景非依存）で判定し、塗り対背景・縁取り対背景は参考併報とする解釈を README の受け入れ診断節に明記した。

## CodeX静的レビューでの追加修正（4回目のレビュー反映、不透明度と回転の追従）

CodeXの3巡目レビューでP1なし・既報修正は妥当と確認。読ませる役の不透明度追従にP2、回転にP3が残っていたため修正した（全562テスト通過、可読性検証はクリーンな読み込みで合格）。

- P2 setOpacity が縁取り・影・下地の不透明度に追従しない: エントリに確定可読性指定（readabilityStyle）を保持し、setEntryOpacity が塗りに加えて縁取り（strokeまたはoutline）・影・下地の不透明度へ同じ実効不透明度を掛けるようにした。出現時の opacity も反映する。ReadabilityBackingObject に setOpacity を追加（文字形の暗い複製は塗りと縁取りを同値に、単位背面の暗い面は元の不透明度との積に）。これでフェードアウト時や opacity:0 で黒い縁取り・影・下地が残らない。フレーズ側も同様。
- P3 setRotation が可読性下地を回さない: setEntryRotation で下地の object も同じ回転にした（通常は update のカメラ正対で上書きされるが、API契約「下地は単位追従」に合わせる）。フレーズ側も同様。
- entry の保持情報を maxBrightLuminance 単体から確定可読性指定（readabilityStyle）へ変更し、setColor の発光抑制と setOpacity の追従の双方に使う。reapplyReadability も readabilityStyle を更新する。

注記: 可読性診断はファイル編集直後の開発サーバの再読み込み中だと一過性に誤計測することがある（HMR）。クリーンな読み込みで再実行すれば安定して合格する（全背景の最小4.69）。
