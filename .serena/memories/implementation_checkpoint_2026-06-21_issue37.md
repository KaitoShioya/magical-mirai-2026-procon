## 位置づけ

マイルストーンM1「譜面・曲プロファイルパイプライン」で、和声の被覆を楽曲の全域へ広げる処理である。コード進行の無和音区間（和音名 "N"）を、解決後の実在和音名と埋め方の種別へ正規化する曲非依存の純粋関数を提供する。本作の協和はY軸スロットにその時刻の和音の構成音を割り当てることで成立し、和音が全域を切れ目なく覆うことを前提とするため（docs/research/07 §1.1・§1.3）、和音が無い区間を埋めて協和の保証を全域へ広げる。下流の音高生成（#36）が解決名と種別を消費し、曲プロファイル生成（#46）が ncRanges を記述して本関数を呼ぶ。

## 最重要の意思決定

- **出力は「解決後の実在和音名」と「埋め方の種別」まで（音高化はしない）**: `src/utils/chordPitch.ts` 冒頭注釈が #37 の出力を解決後の実在和音名と規定する。和音名から音高集合を作るのは #35、安全付加音を加えた7スロット正規化は #36 の責務とする。
- **配置先は `src/profiles/generate/noChordResolution.ts`**: 曲プロファイル型（Chord・NcRange・MusicalKey）を使い profiles に属するため。見せ場生成 #41 と同じ生成層の純関数とする。utils は曲プロファイル型を取り込めないため、調の主和音記号の生成だけを `src/utils/musicalKey.ts` に分けた（「調から和音名を作る」のは「和音名から音高を作る」#35 とは別概念）。
- **埋め方の種別の割り当て規則（#46 が記述、#37 は消費）**: 既定は直前和音保持（previous）、歌唱中の長い無和音区間だけ調の音階（scale）、曲頭は直前和音が無いため scale（docs/research/07 §1.2）。
- **scale はこの段階で調の主和音記号 "Fm" へ正規化する**: 調はファのナチュラルマイナー。安全付加音（短調は♭7度と11度）を加えたFマイナーペンタトニックへの展開は #36 の責務であり、Fm三和音へ縮退させない契約をコメントと README に明記した。
- **異常は文脈付きの例外で早期失敗**: 件数不一致・対応欠落・複数一致による曖昧・previous の前提不成立・解決名の変換不能。黙って代用せず下流に誤りを潜伏させない。

## 採用した数値とその理由（すべて理由を先に述べる）

- 時刻一致の許容差は1ミリ秒: ncRanges は songmap の "N" 区間と同一時刻で記述されるが、生成経路の浮動小数点演算で微小な差が生じ得るため、検証関数 validateProfile の許容差（1ミリ秒、浮動小数点誤差対策）と同じ値・同じ理由を用いる。
- 協和の補助判定にファのナチュラルマイナー音階の音名クラス集合 {0,1,3,5,7,8,10} を用いる: 無和音区間には和音の参照が無いため、協和の基準は調の中心音であり、調内音は協和する。安全付加音を含む協和の網羅証明は #36 のテストに委ねる。
- 主音と種別から主和音記号を作る: ナチュラルマイナーの主和音は短三和音、メジャーの主和音は長三和音であるという標準的な和声に従う。ファ短調なら "Fm"。

## 実データによる事前確認（対象曲TAKEOVER、結論のみ）

`docs/analysis/takeover.songmap.json`（版管理に含まれる）で確認した。無和音区間は6個（和音索引 0・22・24・99・170・209）。合計9783.5ミリ秒で、曲長237250ミリ秒の4.12パーセント（Issueの「4.1%」と一致）。previous の直前和音は、索引22と99が Eb、索引170と209が Fm である。
