# 実装チェックポイント Issue #19 実機性能検証スイート

実装完了。ブランチ `worktree-issue-19-perf-suite`、Pull Request #163（base: main、Closes #19）。型検査・単体テスト（951件、回帰なし）成功。実GPU（NVIDIA GeForce RTX 3050・新しいヘッドレスモードと ANGLE の Direct3D 11 経路、ソフトウェア描画でないことをハーネスが確認）で予算表を計測し、デスクトップ満載が毎秒60フレームに収まること、モバイル相当の劣化はしごが出力されることを確認。失敗系（接続できない状態）で各行の失敗表示と非ゼロ終了を確認。

## ゴールと達成基準
既存の `scripts/prototype-fps.mjs` を、デスクトップとモバイル相当の各描画設定で性能予算表を出す計測ツールへ拡張する。受け入れ基準「デスクトップ60フレーム・モバイル相当の予算表が出る」を、Issue #18 と同一指標（平均フレーム数・最低フレーム数・画素密度倍率・反射とブルームの状態・描画命令数）の一覧出力で満たす。本ツールは計測の道具であり品質ゲートではない。正式な性能の合否判定は Issue #97（描画性能ゲート）と Issue #85（実機テストマトリクス）が担い、二重化しない。

## 確定した前提（設計判断）
- 計測ツールでありゲートではない。フレーム数の不足やソフトウェア描画では終了コードを失敗にせず、計測そのものが成立しなかった行（未捕捉のページ例外、または標本が1件も採れない）があるときだけ非ゼロで終了する。理由＝フレーム数の良し悪し（参照注記の役目）と計測の成否（終了コードの役目）を分けるため。
- モバイル相当（表示領域390×844・端末画素倍率3・処理速度6倍絞り）は保守的な代理基準のため、実GPU計測でも毎秒60フレームに届かず予算注記は「外れる」が並ぶ。これは仕様どおりで、実機での正式判定は #97・#85 が担う。デスクトップ満載は60に収まる。
- 接続先の既定を品質検査ハーネスの設定 `scripts/harness/config.mjs` の `BASE`（5173）へ統一（現行 prototype-fps.mjs だけが5174で不整合だった）。

## 実装内容（ファイル）
- 変更 `src/tools/perf/main.ts`: `renderer.info.autoReset=false` をレンダラ生成直後に設定し、描画関数 `animate` 冒頭（合成描画前）で `renderer.info.reset()`、合成描画後に `lastFrameDrawCalls=renderer.info.render.calls` を保存。`window.__drawCalls=()=>lastFrameDrawCalls`（初期値 null＝最初の描画完了前は取得不能を表し実測0と区別）と `window.__pixelRatio=()=>renderer.getPixelRatio()`（実際に適用された画素密度倍率の実測）を公開。反射（Reflector）とブルーム（合成器の UnrealBloomPass）が1フレームに複数描画を走らせるため、自動初期化を切って合算した1フレーム分を読む（本編 renderRoot.ts と同方法）。
- 変更 `src/types/globals.d.ts`: `__pixelRatio?:()=>number` を追加。`__drawCalls` の型を `()=>number` から `()=>number|null` へ広げ（初回 null 対応）、用途コメントに計測ページ（prototype.html）を追記。既存の代入元（app/index.ts・diagnostics/main.ts は number を返す）は共変性で破綻しない。
- 変更 `src/tools/README.md`: 守る契約に `__drawCalls`・`__pixelRatio` を追記。
- 変更 `scripts/prototype-fps.mjs`: 予算表を出す計測ツールへ書き換え。`launchGpuBrowser`（新ヘッドレス＋ANGLE）で起動、各行を `run-local.mjs` と同じ try-catch-finally で計測、`summarizeFps`（下位5パーセンタイル・最低・平均・標本数を内包）で指標算出、`__drawCalls`・`__pixelRatio` を `page.evaluate` で取得し数値でなければ空値、信頼可否を `isSoftwareRenderer` で判定、`writeReport` で `scripts/.quality-out/perf-budget.json` を書き出す。端末寸法・処理速度絞りは `config.mjs` の `PROFILES` から名前で参照し数値の二重管理を避ける。
- 変更 `package.json`: 実行口 `prototype:fps` を追加。
- 変更 `.serena/memories/dev_infrastructure_notes.md`: 既定接続先の記述を5173統一・`prototype:fps` 追加に更新。

## 予算表の構成
- デスクトップ profile（表示領域1280×720・端末画素倍率1・絞りなし）: D0 満載、D1 反射無効（反射費用の切り分け）の2行。
- モバイル相当 profile: M0 満載 → M1 画素密度↓ → M2 ブルーム解像度↓ → M3 ブルーム無効 → M4 反射解像度↓ → M5 反射無効 の累積単調な劣化はしご6行（画素密度→後処理→反射の順で、下げた負荷を後の行で戻さない）。発光点は全行300で固定。劣化順の根拠＝architecture.md 3.8節・research/03 3節。
- 各行の参照注記（表示のみ・終了コードを変えない）: 60フレーム予算（平均と下位5パーセンタイルの両方が60以上か。根拠＝research/08 3節）、描画命令数100未満か（根拠＝research/03 3節・Issue #18）。取得不能・標本0のときは空値で未達と区別。
