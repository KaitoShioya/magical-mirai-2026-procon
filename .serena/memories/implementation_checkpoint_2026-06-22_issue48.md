## ゴールと達成基準
音楽の時刻と入力の時刻の差で連続評価する、失敗のない床のタップ判定エンジン。受け入れ基準は、(1)タイミング精度が前後40ミリ秒で100パーセント・前後90ミリ秒で0パーセント・点推定の前後60ミリ秒の境界値テスト最低15ケースが確定値と一致、(2)床域でもタップを破棄せず結果を返す（下流が音と最小光点を発火できる）、(3)補正値を変えると判定窓の中心が移動する、である。設計の正典は `docs/idea/concept-final.md` §4・§6、判定窓の数値根拠は `docs/research/04-ux-and-chart-design.md` §1 と `docs/research/07-feasibility-and-parameters.md` §2.4、所属ディレクトリと依存規則は `docs/decisions/architecture.md` §4・§5。

完了の定義: `src/scoring/` 内の純粋関数群と単体テストまで。フレームループへの結線・入力配線・音の発火・光点の描画は #59 へ、軌跡上距離への翻訳と落下式レーンの視覚表現は #49・#57 へ、反応強度と最小光点の下限値は #51 へ、スコア合成とランクは #55・#56 へ、ゲージは #54 へ、較正UIと補正値の保存は #50 へ引き継ぐ。

## 実装方式（採用理由を先に述べる）
判定は時間（ミリ秒）だけで行う。理由は、正典 `docs/research/04` §1 が「内部の判定は音楽の時刻と入力の時刻の差で行い、軌跡上の距離はその視覚的な表現とする」と定めるため、カメラ軌跡は判定で使わない。`src/scoring/` は依存規則上 `profiles`・`rendering`・`tools`・`three` を取り込まないため、`profiles` の Note 型を取り込まず自前の最小入力型を定義する（`src/utils/cameraTrajectory.ts` が `profiles/schema` を取り込まない方針と同じ）。判定窓の数値（40・90・60）は `src/config/tuning.ts` を参照し再定義しない。音程の床値は scoring 単独所有のため scoring 内に置く。

## 主要な設計判断（採用理由を先に述べる。二度の独立レビューで確定）
- タイミング精度は連続曲線1本で表す。満点窓40ミリ秒（1拍343ミリ秒の約12パーセント）と外端90ミリ秒（約26パーセント）の間を直線で結び、外端で0・満点窓の内側で1へ切り詰める。式は `accuracy = clamp01((90 - 中心化済み時間差の絶対値) / (90 - 40))`。点推定60ミリ秒は独立分岐を持たせず曲線上の代表値0.6（(90-60)/(90-40)）として扱う。ユーザー承認。
- 音程精度は完全一致のみ1.0、外したら距離に依らず床値0.2。理由は、本作は外れ音が物理的に存在せず音程JUSTを完全一致で最も明確に定義でき、判定がスロット数に依存せず単純になるため。ユーザー承認。
- 音楽の時刻は engine のゲーム時計を基準にする。`docs/decisions/architecture.md` 154行「判定・得点・ノーツの配置はこの時計（player.timer.position を平滑化・単調化・ずれ補正したゲームの時計）で行う」に従う。研究§1の「真の基準」は時刻の源泉を指す（第2レビューで取り違えを是正）。
- 判定基準時刻は拍格子時刻（beats[note.beatIndex].startTimeMs）であり演出実時刻 note.timeMs ではない。スキーマが両者を二系統に分離しており、現行の拍頭配置（#38）では一致するが、将来のサブ拍演出（#39・#43）で演出実時刻が拍頭からずれると判定がずれるため、呼び出し側が拍格子時刻を解決して渡す（第2レビューで明文化）。
- 3時刻分離: タップの音楽時刻 = フレームのゲーム時計 + (入力の時刻 - フレームの実時計)。入力の時刻とフレームの実時計は同じ高精度時刻基準のため差が取れ、フレーム内のタップ発生時刻のずれを補える。1フレーム約16.7ミリ秒は1拍343ミリ秒の約5パーセントに当たり、無視すると最大でこの幅の誤差が乗るため補間する。
- 信頼性前提: 再生中かつ準備完了かつ非再同期フレームでないと音楽時刻の復元が信頼できないため、信頼性フラグが偽のフレームのタップは床のタップとして返す。フラグの素（isReady・isPlaying・FrameOutcome.didResync）は既存の `src/engine/` が供給し、判定を呼ぶか否かの最終制御は #59 の責務（第1レビューで明文化）。
- 較正の補正値は判定窓の中心を平行移動させる。式は `中心化済み時間差 = (タップの音楽時刻 - ノーツの音楽時刻) - 補正値`。較正で測る「一貫した遅れ」を差し引くと中心が遅れ側へ動いて体感に一致する。補正値の所有は較正UI #50、本エンジンは引数（既定0）で受ける。
- 対応付けは最も近いノーツ点を選ぶ。外端90ミリ秒以内のノーツを (中心化済み時間差の絶対値・スロット不一致を1とする値・ノーツ時刻・id) の辞書順で先頭採用する。第1基準を時間差とすることで正典「軌跡上のノーツ点と反応した瞬間の点の距離」に沿い、同時押し（同一時刻の複数スロット）では時間差が等しくなるため第2基準のスロット一致で各指が自分のスロットへ対応する。窓内にノーツが無い場合は床のタップ（boundNoteId=null・isFloor=true・各精度0・中心化済み時間差は非数）。
- 結果型を最小に保つ: タップの発音と光点に必要な入力側の値（スロット番号・色・座標）は元の Reaction が保持するため `JudgmentResult` へ重複させず、呼び出し側が Reaction と判定結果を対にして下流へ渡す（第1レビューで根拠を明記）。
- 音程精度の0と0.2は別物: 床のタップの0は「比較する正解スロットが存在しない」、音程外しの0.2は「正解スロットは存在するが不一致」を表す（第3レビューで README へ明記）。
