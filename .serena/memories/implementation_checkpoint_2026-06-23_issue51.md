## 実装方式（採用理由を先に述べる）
反応強度は判定（`JudgmentResult`）を入力とする下流処理であり、`src/scoring/types.ts` の「timingAccuracy・pitchAccuracy は #51 反応強度が消費する」という注釈と `src/scoring/README.md` が #51 をこの層で定める前提で記述しているため `scoring` に置く。出力は0以上1以下の数値のみで `rendering` を参照しないため、依存規則（`scoring` は `rendering`・`profiles`・`tools`・`three.js` を取り込まない）に適合する。実 import は `import type { JudgmentResult } from "./types"` のみ。

## 主要な設計判断（採用理由を先に述べる。計画段階の三度のCodexレビューと実装後の妥当性レビューで確定）
- 出力は2チャンネル独立の組。`size`（大きさを駆動する0以上1以下の強度）はタイミング精度のみ由来、`brightness`（明るさを駆動する0以上1以下の強度）は音程精度のみ由来。理由は正典 §6 が両者を別の精度へ対応づけるため。スコアへ寄与する単一の総合値はここで作らず、Issue #55・#56 が各精度と各JUSTを直接消費する。
- 写像は恒等（精度をそのまま強度とする）。理由は、受け入れ基準「精度が高いほど大きく明るい」を単調増加で最も素直に満たし、新しい閾値や係数を持ち込まないため。ユーザー承認。
- 可視下限と実表示範囲は描画層が所有する。光点が完全消失しない最小可視サイズと輝度の下限、および0以上1以下の強度を実寸へ変換する写像は描画層の `reactionToScale`・`reactionToBrightness`（`src/rendering/entities/butterflyReactionMapping.ts`、Issue #61で実装済み）が与える。その具体的な最小値・最大値は描画層の定数（`src/rendering/constants.ts`）が単一の所有元かつ仮値であるため、`scoring` 側のコメントとREADMEへ複製しない。理由は、複製すると描画側の調整時に二か所が食い違うため。
- 非有限値は0へ倒す（例外を投げない）。理由は、既存 `timingAccuracy` が非有限値で0を返すのと同じ規約に合わせ、失敗のない床の方針（判定を止めない。正典 §4）を保つため。下流の蝶の写像は非有限値で例外を投げるため、ここで0へ倒すと有限値だけが下流へ流れ例外を未然に防ぐ。範囲外の値は0以上1以下へ丸める。補助関数 `clampUnitInterval` が非有限値の防御と範囲外の丸めを1つにまとめる。
- 音程精度の3状態をそのまま区別する。床のタップ（対応ノーツ無し、音程精度0）は明るさ強度0、音程を外したタップ（音程精度0.2）は明るさ強度0.2、音程完全一致（音程精度1.0）は明るさ強度1.0。床が最も暗く、外し音がやや明るく、完全一致が最も明るい階調になる。`src/scoring/README.md` が #51 に委ねていた判断。ユーザー承認。
- 入力に `JudgmentResult` 全体を受け取る。理由は判定の単一の出力型を素直に消費でき、将来 `isFloor` 等の参照が必要になっても呼び出し側の契約を変えずに済むため。
