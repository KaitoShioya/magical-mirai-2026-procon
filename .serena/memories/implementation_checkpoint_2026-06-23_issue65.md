## 最重要の意思決定（すべて理由を先に述べる）

- **満ち量と色補間の共通入力は `t = clamp(percentile, 0, 100) / 100`**: concept-final §9「スコアの増加でゲージが蓄積」を満ち量へ写すため。簡易百分位 `simplePercentile`（#55）は得点に対して線形のため `percentile / 100` は正規化した得点に一致し、満ち量はスコア増加に単調比例する。満ち量と色は同一の `t` を使い、百分位からの換算は `fillFractionFromPercentile` の1か所に集約する。
- **色補間の中核 `rankGaugeColorAt(t)` は百分位を知らない純粋関数**: 色補間モジュールに「得点の百分率」という意味を持たせないため。レンダリング層は scoring を実行時に取り込まず（依存規則 architecture.md §5）、百分位からランク添字への変換は統括（`src/app`）が `rankFromPercentile`・`rankOrdinal` で行い、ゲージへは整数のランク添字（0がC・1がB・2がA・3がS）を渡す。
- **色のアンカーを百分位帯の中心（t が 0.125・0.375・0.625・0.875）に置く**: ランク帯は C が0以上25未満・B が25以上50未満・A が50以上75未満・S が75以上100以下で、各帯の中心にその帯の純色を置くと帯の内側では表示文字のランクと同じ純色が支配し帯境界では隣接色へ滑らかに遷移するため。両端はそれぞれの端の色で一定。明度と彩度は線形、色相は最短角度方向で補間。色はランク帯の塗り分けでなく百分位の連続表現であり、帯境界付近では文字のランクと色の支配色が一致しないことがある（仕様）。
- **色域への丸めは最終のガンマ補正sRGBの1段階だけで行う**: 中間のOKLabや線形sRGBで丸めると色相が歪むため、表示可能域への収めは最終段階に限る。色は `Color.setRGB(r, g, b, SRGBColorSpace)` で材質へ設定する。`digitAtlas.ts` のテクスチャと同じくsRGB色空間として扱い、本番 `renderRoot`（出力sRGB・トーンマップ無効）と整合する。2次元層はブルーム非対象かつ材質はトーンマップ無効のため指定色がそのまま出る。
- **所有形態は落下式レーン（#57）と同じくプレイ画面が生成・更新・破棄を持つ**: ゲージの内容が百分位という動的状態に依存し供給源が統括・画面側にあるため。`renderRoot` 所有（音程ガイド #58 の方式）は採らない。
- **文字図版の並びは scoring の正典に従う**: 文字C・B・A・Sを描く `RANK_GAUGE_LETTERS` が `RANKS_ASCENDING` と一致することをテストで固定し、並びのずれで表示ランクと色・帯分けが食い違うのを防ぐ（rendering の実行時コードは scoring を取り込まないため、テストファイルで両者を比較）。

## 受け入れ診断ページの画素読み戻しの対処（理由を先に述べる）

- **判定に使う帯中心の百分位の満ちバー中心画素を読み込み直後に同期で読み戻して控える**: ヘッドレスのソフトウェア描画では読み込みののち時間を置くと描画文脈が失われ（文脈喪失の状態になり描画バッファの寸法が0になる）画素を読めなくなるため。画素読み戻しを行う既存の受け入れ診断（層合成 `layer-composite`）と同じく、読み込み直後に同期で読み結果を控える方式を採る。この対処は受け入れ診断ページ専用で本番の描画経路には入らない。アニメーション描画は文脈喪失中は描かないガードを入れる。

## 計測の定義と採用した定数（すべて理由を先に述べる）

- **知覚的滑らかさのテスト**: 標本間隔を t で0.005刻み（百分位0.5刻み、201標本）、「隣接」を「この刻みで連続する2標本」と定め、隣接するOKLab距離（√(ΔL²+Δa²+Δb²)）について2条件を固定する。条件1「最大が平均の8倍以下」: 滑らかな補間では隣接距離は区間ごとの速さの違い（本配色の3区間で2倍以内）と色相弧の曲率（2倍以内）の積（4倍以内）に収まり、8倍は余裕を持った上界であり、段差があるとその1点だけが平均の数十倍になり検出できるため。条件2「最大が0.02以下」: OKLab距離0.02は知覚しうる微小な段差の目安で、0.005刻みでは最も速い区間でも隣接距離が概ね0.009で下回るため。
- **色変換の既知参照の許容0.01**: 浮動小数の丸めと行列演算誤差を吸収しつつ色のずれを検出できる十分小さい値のため。明度0で黒・明度1で白・明度増加で各チャンネル単調増加を固定する。
- **スモークの色一致の許容0.02（各チャンネル絶対）**: 描画画素は8ビット量子化（1階調が約 1/255、すなわち約0.004）と合成の誤差が乗るため、0.02（約5階調）はこれらを吸収しつつ別の色との取り違えを検出できる。判定の基準色は診断ページが公開する算出sRGB（材質へ設定する値そのもの）と読み戻し画素の両方。
- **文字の縦画素の下限18**: 可読性ゲート（#31）の最小可読画素が18でこれに揃える。2次元層の縦1単位は端末画素で「縦の描画画素数 ÷ 2」に対応するため、文字の単位高さ H を `H >= 2 * 18 / 縦の描画画素数` で下支えする。
- **文字の単位高さの上限0.20**: 文字の中心を縦位置0.89に置くため、上限0.20なら上端が 0.89 + 0.10 = 0.99 で画面上端の+1未満に収まり、縦の短い画面でも切れない。
- **ゲージが任意の縦横比で画面内に収まる**: ゲージ横範囲は [aspect-0.26, aspect-0.08] で、視錐台横範囲 [-aspect, +aspect] に収まる条件は aspect が0.13以上。実機の縦横比は携帯縦（幅390・高さ844で aspect が0.462）でも0.13を上回るため横方向に必ず収まる。縦範囲は縦横比に依らず [-1, +1] 内。
- いずれも単一所有（rendering の本モジュール）の暫定値で、実装後のプレイ検証で調整しうる（★暫定の寸法・色は `fallingLane.ts` と同じ方針）。
