## 変更内容

### Issue #71 結果画面とスコアの受け渡し
- 楽曲終了時に最終スコアを一度だけ確定（凍結）して保持する（src/app/index.ts）。結果画面の表示と成果物画像が同じ値を使い、数値が一致する。
- 表示文字列の整形を単一の関数 src/scoring/resultText.ts に集約し、結果画面と画像が同じ関数を通す。
- 画面への結線は ScreenContext.result を、プレイ画面の結線と同じ形で追加した（src/screens/types.ts）。
- 結果画面 src/screens/resultScreen.ts はライブの3次元の情景の上に薄く重ね、スコアの欄を閉じるボタンで畳める。

### Issue #69 成果物画像の書き出し
- 専用の合成器（src/rendering/bloom.ts に追加）で発光のにじみを含む最終合成を固定解像度へ描き、画素を読み戻す（src/rendering/artifactCapture.ts）。読み戻す描画対象は8ビット整数にした。理由は、合成器の内部描画対象の既定が半精度浮動小数で、8ビット整数の配列へは型が食い違い読み戻せないためである。
- 文字は読み戻した画素を2次元キャンバスへ写し、その上に2次元キャンバスの文字描画で焼き込む。
- 出力解像度は端末の縦横比に追従する（src/rendering/captureEncode.ts）。形式は無圧縮可逆形式（PNG）固定で容量の上限は設けない。保存名は screenshot.png。
- 部分集合フォント生成 scripts/build-font-subset.mjs に成果物の固定文字を加えて再生成した（public/fonts/zen-kaku-gothic-new-subset.woff）。
- 描画基盤 src/rendering/renderRoot.ts に captureArtifact を追加した。
- 受け入れ診断ページ artifact.html と src/rendering/diagnostics/artifact.ts を新設した。

### Issue #63 楽曲終了後の灯し立ち上げ演出
- 既に湖面に灯っている灯し（蝶・ひまわり）に、終了時だけ点灯の盛り上がり（輝度の一過性の増加）を配置順の時間差で重ねる。暗転は挟まず、輝度は基準値を一度も下回らずに基準値へ収束する。
- 進行の計算は純粋な関数 src/utils/finaleReveal.ts に分離した。灯しエンティティ（src/rendering/entities/sunflowerFigures.ts と lanternButterflyFigures.ts）に基準値の保持と applyFinale を追加し、描画基盤に beginLanternFinale を追加して実経過時間で駆動する。
- 動きを減らす端末設定では演出せず、灯しを基準輝度のまま保つ。

### Issue #70 共有機構
- src/app/share.ts。端末がファイル共有に対応していれば共有シートへ、対応していなければ画像の保存とテキストの複写へ自動で切り替える。外部サーバーは用いない。
- 分岐の論理を注入可能な窓口に分離し、単体検証できるようにした。

### Issue #68 撮影モード
- カメラ姿勢の計算は three.js に依存しない純粋な関数 src/utils/photoCameraRig.ts、指の操作の束ねは src/app/photoCamera.ts。結果画面でのみ有効にし、得点状態への参照を持たないため撮影操作はスコア・配置・判定に干渉しない。
- 1本指の操作で視線方向の変更、2本指の操作で平行移動、2本指の指の間隔の変化（ピンチ）で視距離の変更（カメラ位置を視線方向へ前後に動かす）を行う。

## 検証

実行環境は Node.js 22（Node.js 24 はビルドが異常終了する既知問題のため使わない）。

- 型検査3構成成功。単体テスト1801件成功（追加分は結果表示の整形・画素の行反転と出力解像度の算出・立ち上げの進行・共有の分岐・撮影カメラの計算）。本番ビルド成功。
- 出力解像度の長辺を1200画素にした理由は、Issue #69 が許容する正方形寸法1200と一致させ最大面積を1200×1200に収めるためである。縦横比の下限を0.8にした理由は、Issue #69 が許容する縦長寸法1080×1350の縦横比が0.8であるためである。実機で長辺1200画素・縦横比0.8の画像が出ることを確認した。
- 画像が黒一色でないことの判定の下限を平均輝度3にした理由は、読み戻しや描画が失敗すると平均輝度がほぼ0になるため、夜景でもわずかに明るくなる値を下限に置くためである。実測の平均輝度は38であった。
- 立ち上げ演出は輝度を基準値から山を経て基準値へ戻すことで暗転を避ける設計である。実機で輝度が基準（35.4）から山（44.3）を経て基準（35.0）へ戻り、基準を下回らないことを確認した。
- 撮影モードの非干渉は、結果画面でカメラ操作を行いカメラ姿勢が変わる一方で、得点状態（タップ数・ゲージ・百分位・操作音の呼び出し回数）が操作の前後で完全に一致することで確認した。
- 共有機構は、ファイル共有に対応しない環境で画像が screenshot.png として保存されることを確認した。
- 結果画面の下部ボタンに下余白を設けた理由は、画面下端に常設するライセンス表記の帯にボタンが重ならないようにするためである。ライセンス帯の高さは実測66画素で、ボタンの下端736画素がライセンス帯の上端778画素より上にあることを確認した。

## ゴール基準（達成済み）

1. #63 楽曲終了後に情景が立ち上がる。暗転せず基準輝度へ収束する。
2. #69 作品名・曲名・スコア・ランク・百分位・初音ミクの出典を画像内に含み、画面表示と数値が一致する。出力解像度は端末の縦横比に追従する。
3. #71 完成情景として画像が出る。結果画面の数値と画像の数値が一致する。
4. #70 端末により共有方法が切り替わる。外部サーバーを用いない。
5. #68 直感操作で撮影でき、スコア・配置・判定に一切影響しない。

## 当初仕様からの変更（作者の判断）

- 画像形式：当初は容量500キロバイト以下を目標とし超過時に不可逆形式へ切り替える設計だったが、常に無圧縮可逆形式（PNG）で容量の上限を設けない方式へ変更した。
- 保存名：保存・共有する画像のファイル名を screenshot.png にした。
