## 背景と経緯

判定UIは第1次改訂（Issue #199）で音程を画面の縦位置（Y軸）で選ぶ落下ノーツUIにした。作者の実機目視で、右側の落下ノーツを見ながら左側のY軸の番号を確認してタップするのは難しいと分かった。X軸が既にレーンで分かれているため、Y軸で音程を分けるのは重複であった。そこで本改訂で、音程の選択をX軸の7レーンへ移し、タイミングの判定を単一の判定線へ統一した。

## 操作モデルの変更（音程＝X軸の7レーン）

- 音程は画面左側の帯を7レーンに分割し、どのレーンをタップしたかで決める。タイミングは単一の判定線で測る。Y軸は音程・判定に使わない。
- 表示のレーンと入力のレーンを必ず一致させるため、帯の境界を正規化Xの定数として `src/utils/pitchHudLayout.ts` が単一に所有する。入力判定（`src/input/coordinateMapping.ts`）と描画（`src/rendering/fallingLane.ts`・`pitchAxisGuide.ts`）の双方がそこから導く。往復の不変条件 `slotIndexFromNormalizedX(laneCenterNormalizedX(i,n),n)===i` を単体テストで固定する。
- 音程スロット数の検証 `resolveSlotCount` も `pitchHudLayout.ts` へ集約し、入力と描画の双方が同じ正典で検証する（レーン幅が帯幅をスロット数で割る所のゼロ除算・非整数を防ぐ）。
- 音程スロット番号 `slotIndex` の下流（判定 `pitchAccuracy`・素点 `tapBaseScore`・多様性逓減・協和音 `playSlot`→音高・蝶の輝度）は、写像元が縦位置から横位置へ変わるだけで論理は変わらない。効果色 `colorX01` はスコアに寄与しない。

## 判定UIの構成

- 画面左側の帯に縦7レーンを並べ、レーンの間に縦の仕切り線を引く（`src/rendering/pitchAxisGuide.ts`。旧Y軸音程ガイドを転用。slotCount+1 本の仕切り線と横1本の単一判定線を描く）。
- 単一判定線は仕切り線と別マテリアル・別描画順序にする。仕切り線は控えめな寒色の白、判定線は明るい暖色の白で、色味・濃さ・前後でタップの基準だと一目で分かるようにする。
- 各レーンに固有の色を割り当てる（`src/rendering/noteColors.ts`。深夜の暗い背景で隣り合うレーンを見分けやすくするため、色相環をほぼ一周ぶん渡る7色シアン・緑・黄・橙・赤・洋紅・菫）。
- ノーツは発光する立体的な水滴の造形（`src/rendering/noteSprite.ts`。芯・縁の光・外側のにじみ・上部の艶を断片ごとの色計算と加算合成で描く。色は `setColor` で毎フレームそのレーンの色にする。明るさは `setBrightness` で波紋の通過時に脈動）。
- ノーツが判定線に到達した瞬間に、着水点の局所の消滅エフェクト（`src/rendering/noteBurst.ts`。波紋の輪としぶきの粒の寿命付きプール）を出す。これは自動で全ノーツに出る。

## 画面全体の水面の波紋（新規 `src/rendering/rippleField.ts`）

- 得点が0でないタップ（ノーツに当たって素点を得たタップ）のレーンの判定線位置から、同心円の波が画面全体へ広がる。
- 複数の波は重ね合わせで互いに干渉し、輪が交わる所で強め合う。全画面の四角形1枚に断片ごとの波の高さを計算し、加算合成で淡く描いて背景の3次元演出・歌詞を阻害しない。
- 同じ波の高さの式を CPU でも評価し（断片シェーダーと同一の定数・式）、落下中の他のノーツが波面の通過で小さく揺れ明るさが脈動する（他ノーツとの干渉）。
- 結線（タップ駆動かつ得点ゲート）: `src/app/playSession.ts` の `onReaction` が `tapBaseScore(judgment, TAP_SCORE_WEIGHTS) > 0` のとき注入依存 `spawnTapRipple(reaction.slotIndex)` を呼ぶ → `src/app/index.ts` の可変受け口 `tapRippleSink` → `src/screens/playScreen.ts` がレーン組み立て時に `play.registerTapRipple` で `lane.spawnTapRipple` を登録（退出時に無動作へ戻してから破棄） → `src/rendering/fallingLane.ts` の `spawnTapRipple` がレーン中心・判定線Yから波紋を立てる。空打ち（対応ノーツ無し・素点0）では立てない。
- 性能: 活動中の波紋を配列の先頭へ詰め、断片シェーダーは `uCount` で早期に打ち切る。活動中の波紋が無いフレームは `mesh.visible=false` で全画面の描画パスごと省く。同時上限6枚（超過時は最も古い波紋を置き換える）。
- 診断ページ `falling-lane.html` はプレイヤー入力が無いため、各テストノーツの到達時刻で擬似タップ（得点するタップ）を与えて波紋を見せる。

## 主要な数値と採用理由

採用理由を先に述べる。

- レーン帯の幅: 主たる操作は横持ち両手であり、最小タップ目標は48画素（`src/config/tuning.ts` の `MIN_TOUCH_TARGET_PX`）。横持ちの代表幅844画素で帯の幅を正規化Xで0.42に取ると1レーンの幅は 0.42 × 844 ÷ 7 ＝ 約50.6画素となり満たす。
- レーン帯の左端: 画面左端そのものだと最も左の仕切り線が画面端に隠れるため、左端を正規化Xで0.02（844画素で約17画素）に取り、帯幅0.42を保つため右端を0.44に取る。
- 単一判定線の縦位置: 画面下端の出典表記より十分上に置いて重なりを避けるため、正規化Yで0.80（2次元層の縦 −0.60）に取る。
- 波紋の寿命と速さ: 波面が画面の端まで渡り切る時間として2.4秒。寿命2.4秒で画面（縦2単位・横は縦横比の2倍）を渡り切るよう、速さを2次元層の長さ毎秒1.6に取る。
