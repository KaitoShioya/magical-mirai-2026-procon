## このフェーズの発端と判断
- 指摘「全画面のUIがAI slop的で世界観を表現できていない」。色だけの変更（第1段）では不十分で、ボタン・トグル・パネルの形状と質感まで作り替えた（第2段）。
- 設計指針（Web調査の結論）: 暗背景ではニューモーフィズムは破綻し、グロー（発光のにじみ）を主役にグラスモーフィズム（すりガラス）を従に使う。枠線で囲わず「縁を線でなく光」で示す。操作応答時だけ動かし、常時自動で点滅させない。

## 主な変更（src/style.css 中心、描画はすべてコード。AI生成アセット不使用）

### 配色トークン（:root）
- プリミティブ層（生の色）とセマンティック層（用途名）の2層に分離。既存名（--bg・--accent・--text・--text-dim）は温存。
- 逸脱色のピンク（#ff79c6・旧 --accent2）を全廃し、見出しグラデーションの第二色は夜空の菫（--c-iris #9d7cff）、成長グラフ最高棒はオレンジ（--accent-highlight）へ。
- 淡い文字色を #7f8ea3 → #8a99ae へ（菫のパネル上で約4.40:1だったコントラストを約5.0:1へ）。

### ボタンとトグル
- 共通修飾クラス .ui-button--primary（オレンジの灯し＝塗りと多層の発光、ピル形）/ .ui-button--secondary（シアンの光膜＝薄いガラス塗りとぼかした発光、くっきりした1px枠は使わない）を導入し、各 View でボタンへ付与。肯定操作＝primary、副次/切替＝secondary。
- 押下ソナー波紋は document への pointerdown 委譲リスナー1つ（createApp で登録、dispose で解除）。:disabled は波紋なし。撮影除外（data-no-camera）の疑似要素に pointer-events:none。
- 画面隅のトグル（クレジット/設定/較正/これはなに/一時停止）もガラス＋発光の光膜へ統一。

### パネル・タイトル・ランクゲージ
- 常設パネルは backdrop-filter のぼかしで背面の湖を霞ませるすりガラスにし、開くとき panel-rise（260ms、わずかに浮上）。z-index を 1150 にしてトグルより前面に置く。
- タイトル見出しを大型化（最大54px）・字間0.08em・シアン→菫の三段グラデーション＋二重の発光、word-break:keep-all で語中改行を回避。背面に大きくゆっくりのソナーの輪（最大62vh・周期3600ms・柔らかい発光）。
- src/rendering/rankGauge.ts: 満ちの上端に光る水面の線（放射状グローを横長に・加算合成・満ちと同じランク色）を追加し上昇させる。満ちの本体の色は正確なランク色のまま。

### 書体（OFL運用）
- 見出し用 M PLUS 1 を導入（scripts/build-ui-font-subset.mjs が UI見出し文字へ絞った woff2 を生成。wght 700 固定で約39KB）。@font-face を style.css に追加し見出しへ適用。本文と小ラベルはシステムフォント維持。
- 出典: src/typography/kineticText/fontCredits.ts に MPLUS_1_CREDIT、registry.ts の fonts へ追加、README とアプリ内クレジットへ記載、readmeConsistency.test.ts の必須項目へ追加、public/fonts/m-plus-1-OFL.txt 同梱。M PLUS 1・Zen Kaku Gothic New ともに SIL Open Font License 1.1。

### アクセシビリティ
- 全操作要素に :focus-visible の可視フォーカス枠（:focus 併記はせず、マウス押下で枠を出さない）。
- 覆い「触れて再生」（div）に role/tabIndex/keydown を付与し Enter・Space で再生（Space は preventDefault で画面スクロールと二重作用を防ぎ、hidden 中は反応しない）。src/app/overlay.ts。
- prefers-reduced-motion で波紋・パネル浮上・ボタンの移動を止める。較正の点滅とメーター針は機能上の合図のため残す。

### 不具合修正
- パネル開時にパネルの閉じるボタンと画面隅のトグルが重なる問題（同じ z-index 1100 が原因）→ パネルを 1150 にして前面で覆う。
- 結果画面の閉じるボタン（✕）が右上のトグルと重なる問題 → スコア欄に上端のトグル列の高さぶんの上余白を与えて下げる。

## 主要な数値と採用理由（採用理由を先に述べる）
- コントラスト比 4.5:1 以上: 歌詞の可読性方針（任意背景で4.5:1）と同一基準にして作品全体の可読性基準を統一するため。測定の最悪条件はパネル上部の最も明るい色（#2a2150）。
- UI見出しサブセットの上限 200000 バイト（各ファイル）: 既存の歌詞用サブセット検査がモバイル回線の1ファイルの読み込み時間を抑えるため同じ上限を課しており、UI用も同基準に揃えるため。生成結果は約39000バイト・欠字0。
- 実行環境 Node 22: Node 24 は本番ビルドが異常終了する既知事象があり .nvmrc も Node 22 を指定するため。
- 水面の線の高さ 0.035（2次元層の単位）: 最も満ちが低い検証点（百分位12.5＝満ち0.125）でも、満ちの中心（色の正確さを測る点。満ちの上端と中心の間隔は約0.031）に発光が届かないよう小さく収め、満ちの本体の色を正確なランク色のまま保つため。
