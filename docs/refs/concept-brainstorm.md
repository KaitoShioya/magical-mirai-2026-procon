## 0. 設計空間の整理（ブレストの座標軸）

### やりこみの2形態（ユーザー許容済み）と中間形態

```
A. 分離型（作ってから観る）        C. ハイブリッド             B. 同時進行型（ゲーム）
   構成エディタ/VJ仕込み    ←→   プレイの結果が作品になる   ←→   リズムアクション
   創作の達成感                    「操作=創作」               反射の快感
   innovation軸に強い                                          初見の楽しさに強い
```

**鍵となる問い: 「上手く操作する程気持ち良い」の"気持ち良さ"の正体は何か？**

| 気持ち良さの源泉 | 実現手段 | 対応する審査軸 |
|---|---|---|
| リズムが合う快感（音ハメの主体化） | ビート同期入力+判定 | クリエイティビティ |
| 画面が応答して豪華になる快感 | 入力品質→演出リッチ化 | クリエイティビティ |
| 成果物が残る快感（創作） | プレイ結果がアーティファクト化 | **イノベーション** |
| 上達が見える快感 | スコア/グレード/解放要素 | 完成度（リプレイ性） |

→ 4つ全部を1本のループに通すのが理想形。

### 規約との接点（先に妥協点の枠を決める）

1. **効果音**: 「楽曲の一部と誤認される使用」は不可 → 付加音は**操作フィードバック音**（SE）として設計。カメラ機材音・UI音など「明らかに楽曲外」の音色を選ぶ。音量バランス控えめ+設定でOFF可。素材は効果音ラボ/ニコニコモンズ等の規約OK素材（出典をアプリ内明記）
2. **AI生成素材不可** → 視覚素材は (a)コード描画（Canvas/WebGL/SVG） (b)自作ピクトグラム (c)権利OK素材のみ。**テキスト表現主役の方針はこの制約の最適解そのもの**
3. **静的アプリ** → 保存系は localStorage、共有系はURLハッシュエンコード（サーバ不要で「作品の共有」が可能）
4. **動作環境明記** → PC Chrome を主軸、スマホは対応範囲を明示（タップ操作は片指で完結させる）
5. **募集期間中の内容公開禁止** → 応募者側の制約。アプリ内共有機能自体は問題なし

## 1. コンセプト候補（発散）

### 案1 『リリックを撮る』— 撮影型リズムアクション ★推奨

**一行**: 疾走するリリックビデオを「撮影」する。ビートに合ったシャッターは奇跡の一枚を生み、曲が終わると君だけのアルバムが完成している。
**曲**: シャッターチャンス（115 BPM・拍間522ms）

**コアループ**:
1. 画面全体がファインダー。参考動画の文法で常時全力疾走するリリック演出が流れる（**操作しなくても疾走感は100%担保** — 観るだけでも成立）
2. タップ/クリック=シャッター。**ビート/歌詞の発声タイミングに近いほど高評価**（PERFECT: ±80ms / GOOD: ±160ms — 拍間522msなら成立する判定幅）
3. 撮った瞬間の画面構図が「写真」として確定し、ポラロイド風カードで画面端にスタック（公式MVの文法と同根）
4. 連続成功でフィルムグレード上昇 → **演出がリッチ化**（モノクロ→2色→蛍光色解放、エフェクト追加、連写モード解放 at サビ）
5. 曲終了 → 撮った写真が自動レイアウトされ「アルバム」完成。グレード評価+ベストショット表示。**アルバムはURLハッシュで再現可能**（撮影タイミング列をエンコード）→ リプレイで「完璧なアルバム」を目指すやりこみ

**4軸との整合**:
- ①疾走感: ベース演出は自動進行で常時全力。設計文法（1文字1拍/字間ホールド/円状回転/重ね）をフル適用
- ②やりこみ: タイミング精度→演出リッチ化→アルバム品質、の3段増幅。スコアと創作物の両取り
- ③テキスト表現: 主役。写真カード化により「テキスト演出の一瞬を切り取る」という再帰的なテキスト表現
- ④付加音楽表現: シャッター音・フィルム巻き上げ音・連写音がビートにスナップ → **操作SEという安全な立て付けで音ハメが成立**。PERFECT時だけ「カシャッ」が完璧に拍に乗る=上手いほど音楽がリッチに聞こえる

**曲との噛み合わせ（songmapデータ根拠）**:
- 「いつだってシャッターチャンス」×4回 → 円状回転+重ね技法の定点観測ポイント（毎回演出が進化していることが分かる）
- サビ10区間 → 連写モード(ストロボ演出)の見せ場が10回
- 冒頭3秒でサビ → イントロ2小節は「AUTO」デモ撮影で文法を見せ、Aメロから操作を渡す
- 歌詞がカメラ用語の塊（半押し/レリーズ/ファインダー/ピント/ストロボ）→ **操作と歌詞が意味レベルで同期**

**審査3軸**: クリエイティビティ◎（音ハメ撮影の快感）/ イノベーション◎（「リリックビデオを撮影する」行為の発明、成果物の共有）/ 完成度○（判定・演出・アルバムの3システム、スコープ管理可能）

**リスク**: 撮影UIの説明なし理解（→冒頭AUTOデモで解決）/ 写真カードの画角切り出しの実装（Canvasスナップショット）/ スマホでの判定精度

### 案2 『TAKEOVER』— 乗っ取り型ライブ介入

**一行**: 完璧に整ったリリックビデオを、ユーザーの介入が壊し、塗り替え、最後は完全に「乗っ取る」。
**曲**: TAKEOVER（175 BPM・拍間343ms）

**コアループ**: 自動疾走するミニマル白黒リリックビデオ（the hole文法）に、2拍/4拍単位のターゲット（Clap to the Beat!）が出現。成功するたび TAKEOVER RATE が上昇し、画面がユーザー色に侵食される（白黒→色反転→グリッチ→文字破壊が解放）。ラスサビで100%なら「完全乗っ取り」エンディング。

**強み**: 曲名=ゲームメカニクス=演出が三位一体。175BPM・スタッカート55%は「観せる疾走」の極致。コール&レスポンス構造（ClaptotheBeat×4）が操作誘導と完全一致。
**弱み**: 拍間343msで操作はどうしても間引きになり「主体的に音ハメしてる感」が案1より薄い。歌詞密度8.3字/sでは可読性と演出の両立が高難度。成果物が残らない（スコアのみ）。
**審査3軸**: クリエイティビティ◎ / イノベーション○ / 完成度△（演出物量が最大）

---

### 案3 『LYRIC DIRECTOR』— 構成エディタ×VJ型（分離型の極）

**一行**: フレーズごとに演出技法を選んで自分のリリックビデオを「演出」する。再生して、磨いて、共有する。
**曲**: 任意（3曲対応も可能）

**コアループ**: タイムライン上のフレーズに表現プリセット（スマッシュカット/字間ホールド/円状回転/重ね/縦伸ばし/ブラックアウト）を配置 → 再生で確認 → 構成はURLハッシュ化して共有。ライブモードではVJ的にリアルタイム切替も可。

**強み**: 「誰でもリリックビデオの演出家になれる」= **未来の創作文化の直球**でイノベーション軸最強。TextAliveの本来思想（リリックビデオ制作支援）とも響き合う。
**弱み**: 初見の楽しさが薄い（編集は敷居）。疾走感は「観る時」にしか出ず、操作自体は静的。気持ち良さが遅延報酬型でコンセプト軸②の「操作する程気持ち良い」と微妙にズレる。工数最大。
**審査3軸**: クリエイティビティ○ / イノベーション◎ / 完成度△（UI工数膨大）

---

### 案4 『最後の音楽隊』— 演奏参加型ナラティブ

**一行**: 「あなた」が叩くビートが、空っぽだった歌声に色を与える。世界最後の音楽隊の一員になる。
**曲**: 世界最後の音楽隊（150 BPM）

**コアループ**: 会話文「」パートでは観る、地の文では叩く。叩いたビートの精度で世界に色が差していく（色の無い世界→色を放つ、の歌詞構造を可視化）。声量最大の曲なので `getVocalAmplitude` 連動の縦伸ばし/渦が主役。

**強み**: 物語と操作の意味的統合が最も美しい。情緒で勝負できる唯一の案。
**弱み**: 疾走感軸では明確に劣る（叙情曲・サビ2区間・4:10の長尺）。「上手いほど気持ち良い」より「参加して感動する」寄り。
**審査3軸**: クリエイティビティ○ / イノベーション○ / 完成度○

### 推奨: 案1を主軸に、案3の「成果物=創作」を内包するハイブリッド

**『リリックを撮る』= プレイ(案1) → アルバムという作品が残る(案3の精神) → URLで再現共有**

- 案1のままで案3のイノベーション価値（創作文化）を回収できる: 「撮影」は実質**ワンタップの演出選択**であり、アルバムは**ユーザーの編集作品**である

## 3. 次フェーズへの宿題（技術調査項目）

1. **文字グリフ操作**: Canvas2D `fillText` vs パスデータ化（opentype.js等）— 縦伸ばし・渦変形・文字内ズームの実現手段とフォントライセンス（SIL OFL系の太ゴシック候補選定）
2. **判定とレイテンシ**: `player.timer.position` の精度、AudioContext出力遅延補正、タップ→判定→演出の遅延予算（スマホ込み）
3. **画面スナップショット**: 演出中Canvasの一部矩形を写真カード化する高速キャプチャ（`drawImage`転写 vs `toBlob`）
4. **URLハッシュ共有**: 撮影タイミング列+判定結果の圧縮エンコード設計（数百バイトに収まるか）
5. **SE素材**: 効果音ラボ/ニコニコモンズのカメラ系SE（シャッター/巻き上げ/ストロボチャージ）の規約確認と候補リスト
6. **パフォーマンス**: 文字パーティクル量とモバイル60fpsの予算、PixiJS(WebGL) vs Canvas2D の選定
7. **the hole式音ハメ**: `findBeatChange` でのrAF内トリガ精度検証
